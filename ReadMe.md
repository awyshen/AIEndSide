
# 意图识别与指令解析技术方案

## 1. 需求分析

### 1.1 业务背景
基于《Solemate BERT指令说明》文档，本系统需要实现端侧环境下的意图识别和指令解析功能。

### 2.3 LLM集成方案

#### 2.3.1 提示词设计

```python
PROMPT_TEMPLATE = """
你是一个意图识别专家，请分析用户输入并进行意图分类。

用户输入: {user_input}

意图类型列表:
1. volume_control - 音量控制相关
2. music_control - 音乐播放控制
3. app_control - 应用程序控制（视频、爱奇艺等）
4. projector_control - 投影仪控制
5. robot_control - 机器人控制（导航、充电）
6. assistant_control - 助手控制（休眠）
7. chat - 聊天模式

请输出JSON格式结果：
{{
    "intent": "意图类型",
    "value": "具体操作值",
    "params": {{参数键值对}},
    "confidence": 置信度(0-1),
    "tasks": [任务列表，支持多任务]
}}

注意：
- 如果是多任务，tasks数组包含多个任务对象
- 如果无法识别，请返回 intent: "unknown"
- 置信度低于0.7请标记为unknown
"""
```

#### 2.3.2 API调用封装

```python
class QwenAPI:
    def __init__(self, base_url="http://10.61.85.20:32685/v1"):
        self.client = OpenAI(
            api_key="EMPTY",
            base_url=base_url
        )
    
    def classify_intent(self, user_input):
        prompt = PROMPT_TEMPLATE.format(user_input=user_input)
        response = self.client.chat.completions.create(
            model="Qwen3.5-0.8B",
            messages=[{"role": "user", "content": prompt}],
            temperature=0.1,
            max_tokens=512,
            timeout=300
        )
        return response.choices[0].message.content
```

## 3. 性能优化策略

### 3.1 端侧优化

| 优化策略 | 实现方式 | 预期收益 |
|---------|---------|---------|
| 规则优先 | 先匹配规则模板，再调用LLM | 减少50%以上LLM调用 |
| 缓存机制 | 缓存高频指令结果 | 降低重复计算 |
| 模型量化 | 使用4-bit/8-bit量化 | 内存占用降低50-75% |
| 异步调用 | 并发处理多任务 | 提升吞吐量 |

### 3.2 延迟优化

```python
# 响应时间目标分解
├── 预处理: ≤30ms
├── 规则匹配: ≤50ms
├── LLM调用: ≤200ms (含网络传输)
├── 结果融合: ≤20ms
└── 总计: ≤300ms
```

### 3.3 资源管理

- **内存限制**: 单次推理内存占用 ≤512MB
- **线程池**: 限制并发数为CPU核心数
- **超时控制**: LLM调用超时300ms

## 4. 错误处理机制

### 4.1 不确定性处理

```python
CONFIDENCE_THRESHOLD = 0.7

def handle_uncertainty(result):
    if result["confidence"] < CONFIDENCE_THRESHOLD:
        return {
            "query_type": "unknown",
            "reason": "无法确定意图，请重新表述",
            "handover": True  # 移交下游处理
        }
    return result
```

### 4.2 异常场景处理

| 场景 | 处理策略 |
|-----|---------|
| 网络超时 | 返回缓存结果或规则匹配结果 |
| 模型服务不可用 | 降级到纯规则匹配 |
| 输入为空 | 返回错误提示 |
| 多意图冲突 | 选择置信度最高的意图 |
| 无法解析参数 | 返回参数缺失错误 |

## 7. 方案评估

### 7.1 任务类型适应性

| 场景类型 | 方案能力 | 说明 |
|---------|---------|------|
| 单任务 | 强 | 规则匹配+LLM增强，准确率高 |
| 多任务 | 中 | 支持简单多任务分割，复杂场景需优化 |
| 模糊意图 | 中 | 依赖LLM推理能力 |
| 上下文对话 | 弱 | 当前方案不支持上下文 |

### 7.2 潜在问题与优化方向

| 问题类型 | 风险描述 | 优化策略 |
|---------|---------|---------|
| 误识别 | 相似意图混淆（如"关闭音乐"vs"关闭视频"） | 增加特征词权重，优化提示词 |
| 漏召回 | 未收录的指令模式 | 持续扩展规则库，LLM兜底 |
| 多任务冲突 | 任务顺序歧义 | 引入时间顺序标记 |
| 性能瓶颈 | 复杂推理延迟高 | 模型量化，本地部署 |

### 7.3 创新优化建议

1. **混合推理架构**: 规则快速路径 + LLM深度路径
2. **动态置信度调整**: 根据输入复杂度动态调整阈值
3. **增量学习**: 在线收集用户反馈，自动更新规则库
4. **意图聚类**: 对相似意图进行聚类，提升泛化能力
